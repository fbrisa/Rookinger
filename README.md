= Rookinger =

== What does this project do? ==
* It uses map-based script (SCAR) to adjust Wikinger gameplay without modifying the files of the mod.
* It aims to create a more balanced gaming environment for Wikinger PvP players by basing the adjustments on the consensus of the most experienced players that are still active.33

== What are the known limitations of the map-based script? ==
* The changes only apply when you play this map together with Wikinger mod.
* Not everything in the game can be changed by this method; for example the AoE radius of a weapon cannot be changed. Read this post for details.

== What rules should I follow if I want to be part of it? == 
* Do not share anything of the project with anyone outside this Discord server.
* Participate the discussion and gameplay testing.

== Preliminary Consensus about Call-Ins: == 
=== Base Pricing ===
* Call-ins should generally cost more than their buildable equivalents, but the * premium should remain moderate.
* Infantry should receive little or no additional manpower cost.
* Vehicles and tanks may receive additional Fuel and/or Manpower costs, with heavier * units generally receiving a stronger penalty.
* Multipliers should likely vary by unit category rather than using one universal * multiplier.
* Exact Fuel multipliers remain unresolved and should be tested on a case-by-case basis, especially considering Tier, map income, and the unit's base cost.
 
== Additional Factors ==
* Pre-applied paid upgrades should generally be added at 100% of their normal cost.
* Doctrine-specific modifiers should be handled in a later balance phase rather than the initial pricing formula.
* Randomized call-ins should use weighted-average pricing, while keeping the strength of different outcomes reasonably close.
* Veterancy pricing remains unresolved and needs further discussion/testing.
=== Exceptions ===
* One-time, Ace, and other special call-ins may receive individually tuned pricing instead of strictly following the default formula.

== Composition ==
* If default pricing makes a call-in excessively expensive, adjust or downsize its composition rather than overriding the pricing rules.
* Where appropriate, oversized multi-unit call-ins could be redesigned as repeatable call-ins to reduce extreme power spikes.
